# src/Blazix.Primitives/Interop

The twins: the C# half of each JavaScript module (ADR 04 §3). Internal to the library (ADR 08 §1); parts talk to twins and never to `IJSRuntime`.

## Inputs

- `docs/decisions/04-js-interop-boundary.md` §3 (contract, decision points), ADR 01 (Server floor), ADR 06 §1 (twin contract tests), ADR 08 §3 (`<Module>Twin`), ADR 16 rule 4 (one `JsonSerializerContext`).
- `../js/twin.ts`, `../js/decide.ts`, `../js/event-info.ts`: the JavaScript side of the same contract.
- `../Events/EventSnapshot.cs` (Track 2): the event snapshot and its JSON names, which `../js/event-info.ts` mirrors.

## Job

- `TwinBase<TTwin, TOptions>`: lazy `import()` of the module on first use; `AttachAsync(ElementReference | string, options)` returning a `TwinHandle<TOptions>` per attached part, idempotent per element; the one `DotNetObjectReference<TTwin>` the module calls back through; `Ping` and `Decide` as `[JSInvokable]` methods; `DisposeAsync` that releases every handle, the reference and the module. A `JSDisconnectedException` (the Server circuit is gone) turns every call into a no-op rather than an exception in a part's lifecycle method.
- `TwinHandle<TOptions>`: `UpdateAsync(options)` and an idempotent `DisposeAsync()`; `update` after `dispose` is a no-op.
- `TwinOptions`: the base of every options record; `Style` is the consumer's merged style string, sent on `attach` and on every `update` (handover at attach).
- `DecisionPolicy` and its kebab-case literals (`run`, `stop`, `start`, `prevent-and-stop`).
- `ButtonTwin` (module `button`): `ButtonOptions` carries the mechanism's configuration (`Disabled`, `FocusableWhenDisabled` with `null` for unspecified, `Native`, `Composite` as the part resolved it, `PressAndHold` with the 400/60 ms and 8 px defaults, `ReportInteractionType`, `DevelopmentChecks`, which defaults to the development warnings switch, and four options sent only when set: `HiddenInput` (the hidden-input bridge of Switch, Checkbox and Radio: a root click is default-prevented and forwarded with its modifiers to the checkbox or radio input the part renders as its next sibling, past an `<input type="hidden">`, found by position at click time because it has no `id` under `NativeButton`; under a `RenderFunction` callback this assumes the callback renders one top-level element), `ReadOnly` (the bridge ignores root clicks and reverts input clicks) `SuppressEnter` (an Enter keydown is prevented and never activates; Checkbox and Radio) and `InputItem` (Toolbar.Input: no key activates the element and its Space is typed; the disabled, focusable key prevention and press suppression stay)). `ActivationDecider` is the C# chain of the `activate` decision point: return `Stop` when a consumer handler called `PreventPartHandler()`. `ToggleDecider`: the C# request of the `toggle` decision point, asked inside the bridged input's click on WebAssembly; `Stop` reverts the box natively (ADR 04 Amendments 2026-10-22, chosen by the user 2026-10-22). Events: `Toggled` (`ButtonToggle`: the input's new `checked` and the click it received, when the toggle was not decided synchronously, which is always on Server), `InteractionReported` (the literal `mouse`, `touch`, `pen`, `keyboard` or empty, with the event), `HoldTicked` (the event that started the sequence, every tick), `HoldStopped` (the release), `HoldClicked` (a click that performs the single action), `NativeButtonMismatched` (the declared mode). The part renders the button attributes itself; the module writes none.
- `DomTwin` (module `dom`): `DomOptions` turns primitives on per element: `Checked` (the hidden checkbox or radio input's property, set on attach and on every update, never inside a native click) with `CheckedRestores` (a count the part raises after a request that left its value different from a native click's, so an unchanged value still sends an update; ADR 04 Amendments 2026-10-22), `Indeterminate` (the checkbox input's property, re-asserted inside a native click), `LiveRegion` (the announcement marker), `Image` (`ImageLoadOptions`: the source properties, `KeepMounted` to derive from the attached `<img>` instead of a probe, `HideWhenLoaded` for the fallbacks' ids, separated by spaces). Event: `ImageStatusChanged` with `loading`, `loaded` or `error`, once per change. The module's measuring and observing helpers have no twin: other modules import them.
- `TransitionsTwin` (module `transitions`).
  - `TransitionsOptions` holds:
    - the machine input `Open`;
    - the values the element was rendered with, read on `attach` only: `Mounted`, and `Status` as a `TransitionStatus?` travelling as the literal `starting`, `ending`, `idle` or nothing;
    - the machine options `EnableIdleState` and `DeferEndingState`, fixed per part;
    - `KeepMounted`, `HiddenUntilFound`, `HiddenWhenUnmounted` (a container is hidden at exit end; an indicator is not), `SuppressEndingStyle` (a kept element plays no exit), `ReportOpenComplete`, `RevealOnBeforeMatch`, `UnmountRequests` (a count C# raises to end an exit itself), and `ExternalExit` (no exit watcher: the exit ends only when `UnmountRequests` increases; the Collapsible Root and Trigger, whose exit ends with the panel's);
    - `OpenSelector`, the selector the element matches while rendered open (`[data-open]`, `[data-panel-open]`, `:not([aria-hidden])`): when set, the module reads the open input from the DOM after every render, before paint;
    - `Style`, applied only when set.
  - There is no `AnimateInitialOpen` field: C# renders the initial status and sends it as `Status`.
  - Events, each raised once per message:
    - `StatusChanged` (`TransitionStatusChange(TransitionStatus? Status, bool Mounted)`);
    - `TransitionCompleted` (`false` for an exit, after which the element is unmounted and its status unset; `true` for an enter).
  - The reveal:
    - `RevealDecider` (`Func<EventSnapshot, DecisionPolicy>`) is the C# chain of the decision point `reveal`: it requests the open and returns `Stop` when the request was canceled. It runs on WebAssembly only, inside the dispatch.
    - Elsewhere the module applies `run` and invokes `OnRevealRequest`, which returns `Task<bool>`: the answer of `RevealRequestHandler` (`Func<EventSnapshot, ValueTask<bool>>`), whether the part is open once the request ran. The module re-collapses the element a frame after a `false` answer.
- `CollapsibleTwin` (module `collapsible`, the Collapsible and Accordion panel's component module).
  - `CollapsibleOptions`: `Open`; `Mounted` and `Status` as the element was rendered (read when the module starts on an element); `KeepMounted`, `HiddenUntilFound`; `SuppressOpenAnimation` (the one-shot `animation-name: none` of an initially open or re-attached panel, read when the module starts on an element); `PanelId` (by which a withheld or replaced element is found again); `OpenSelector` (`[data-open]`); `Style`, the consumer's merged string, which the module composes the whole `style` from.
  - Events, each once per message: `ForcedIdleChanged` (`PanelForcedIdleChange`: the panel shows itself settled during a motion-skipping open), `ExitCompleted` (`OnTransitionComplete` with `open: false`: the exit ended, the module has hidden the element), `AnimationTypeChanged` (`PanelAnimationTypeChange(Type, Mixed)`).
  - The reveal is `TransitionsTwin`'s: `RevealDecider` on WebAssembly, `OnRevealRequest` answered by `RevealRequestHandler` elsewhere.
- `CompositeTwin` (module `composite`, the roving group of one root element).
  - `CompositeOptions`: the root's configuration, `Orientation` (the literal `horizontal`, `vertical` or `both`, the default), `LoopFocus` (`true`), `EnableHomeAndEndKeys`, `StopEventPropagation` (`true`), `HighlightItemOnHover`, `ModifierKeys` (a subset of `Shift`, `Control`, `Alt`, `Meta`; empty), `DisabledIndices` (`null` reads the disabled state from the document), `Direction` (`ltr` or `rtl`), `Items` (`CompositeItemRegistration(Id, TabIndex)`: the element id the module resolves, and the consumer's `tabindex`, which the module never writes over), `SelectOnNavigation` (the pending-navigation flag and the focus-driven selection of a radio group), `ReportFocusLeave`, `ReportHighlight`. `Style` stays unset: the module owns no style.
  - Events, each once per change: `HighlightChanged` (the index, from `CompositeHighlightChange`), `FocusLeft` (the `focusout` snapshot, from `CompositeFocusLeave`), and `KeyHandled` (option (i) of ADR 04's note of 2026-10-22, chosen by the user 2026-10-23) (the `keydown` the module handled and stopped without running the C# chain, from `CompositeKeyHandled`, only with `ReportHandledKeys`).
  - Decision points, both with fallback `run`: `NavigatePoint` (`navigate`, before the module handles a key) answered by `NavigationDecider`, and `SelectPoint` (`select`, before it clicks a focused item's input) answered by `SelectionDecider`. The names were chosen by the user 2026-10-22.
  - From `attach` the module writes every item's `tabindex`; C# renders `-1` and never another value. The behaviours that drive the twin are in `../Composite/`.
- `FormTwin` (module `form`, the field and form infrastructure's mechanism module; the field half from M2 track 1).
  - `FormOptions` has one nullable record per attaching role. `Control` (`FormControlOptions`) carries `FormId`, `CustomValidity` (the field's own message, `null` to withdraw it), `Controlled`, `Value`, `DefaultValue`, `Revision` (an increase asks for a `sync` report), `ReportKeys`, `Disabled`, `ReportEvents`, `FocusTarget`, `AutoFocus`, `EnterSubmit` (a box's root: Enter submits the hidden input's form) and `LabelFallback` (a hidden input: look for its native label and report the label's id in a `label` report's `Value`); the last two are M2 track 5's, settled by the orchestrator 2026-10-23 (ADR 04 Amendments 2026-10-23). `Label` (`FormLabelOptions`) carries `Native`, `ControlId`, `Decides` and `DevelopmentChecks`. Track 2 adds `Submit`.
  - Events, each once per message: `ControlReported` (`FormControlReport`: `Type` `input`/`blur`/`keydown`/`enter`/`sync`/`focus`, `Value`, `Validity` (`NativeValidity`: the eleven flags, `ValidationMessage`, `WillValidate`, `Eligible`, `OwnMessageInstalled`), `Event`, `SameForm`, `Revision`) and `LabelMismatched` (`LabelMismatch(ExpectedNative)`).
  - The decision point `label` (`LabelPoint`) runs `LabelDecider` on WebAssembly; elsewhere the module applies `run`.
  - The submit half (M2 track 2): `Submit` (`FormSubmitOptions`: `Token`, the form's never-rendered token its controls carry as `FormId`; `FocusRevision`, `Focus`) for a form element. The invocation `OnSubmitRequest` (`FormSubmitRequest`: the submit snapshot, `SubmitterId`, a `FormControlState` per enrolled control) returns the JSON of a `FormSubmitAnswer` (`submit`, `blocked` with `Focus`, or `handled`), produced by `SubmitHandler` (`Func<FormSubmitRequest, Task<FormSubmitAnswer>>`).
- `TransitionStatusRules` (`Initial(open, enableIdleState, animateInitialOpen)` and `Evaluate(open, mounted, status, deferEndingState)`, both returning `(bool Mounted, TransitionStatus? Status)`): the C# half of the machine. It covers a part's first render and the render that applies a new open state. The `transitions` module runs the same evaluation step for an attached element; `js/test-support/transition-evaluation.cases.json` tests both.
- `TransitionStatus` (`public enum TransitionStatus { Starting, Ending, Idle }`, namespace `Blazix.Primitives`, file `TransitionStatus.cs` beside its first consumer): a part declares `[property: MirroredField] TransitionStatus? TransitionStatus`, `null` being the unset status.
- A part owns its twin: a callback carries no element key, so one twin attached to several elements cannot tell their reports apart. The twin's host element may be its Root's element (ADR 04 Amendments 2026-10-21, issue 64): the preload `Avatar.Image` attaches its own `DomTwin` to the `Avatar.Root` element, because the `<img>` exists only once loaded, and keeps one live handle. A part's twin may also host an element the part renders beside its own (M2 track 4, settled by the orchestrator 2026-10-22 under ADR 04 Amendments 2026-10-21, the Root-element reading): `SwitchRoot` (and Checkbox and Radio after it) attaches a `DomTwin` to the hidden input it renders after its element, by the input's captured `ElementReference`, beside the `ButtonTwin` on its root; the attach message per twin is accepted. `dom` and `button` own no style property, so their options leave `Style` unset and the part keeps rendering its style; `transitions` applies `Style` only when a part hands its style over.
- The shared enums these literals become (`InteractionType`) arrive with their first part; the twins pass the literals until then. `TransitionStatus` arrived with its twin (track 5). `ImageLoadingStatus` arrived with Avatar (track 7, `../Avatar/ImageLoadingStatus.cs`); `DomTwin` keeps reporting the literals and `AvatarImage` maps them.
- `BlazixJsonContext`: `EventSnapshot`, every options record and every callback payload. Options and payloads cross the boundary as JSON strings the twin serialises and deserialises itself, so the runtime's own serializer only ever sees strings, `ElementReference` and object references (trim- and AOT-safe without configuring the runtime's resolver).

## Outputs

- One `<Module>Twin` per JavaScript module, exposing the module's callbacks as typed events for the parts.

## Human check

- A twin's `[JSInvokable]` callback does one state change per message and is never called per frame.
- A new options record or payload is listed in `BlazixJsonContext` and has an L2 twin contract test.
- `OnDecide` runs synchronous consumer handlers only; nothing awaits inside a decision (ADR 04 §3).
- A press-and-hold tick is a report, never a decision: its result is state, so C# stops a sequence by sending `Disabled` (ADR 01 decision 1).
- `FormTwin`, `FormOptions`, the form payloads: field-and-form-infrastructure.md (FFI-ALG-01/02/04/16, FFI-FRM-09/10, FFI-STA-09, FFI-PTR-01..04, FFI-EDGE-02/06/07), field.md (FLD-API-15/16, FLD-DOM-11, FLD-KEY-01/04, FLD-EVT-09, FLD-FOC-04); ADR 04 §1 (form row) and Amendments 2026-10-18 and 2026-10-22; ADR 01 Amendments 2026-10-22.
