# src/Blazix.Primitives/js

The TypeScript side of the library: one module per row of ADR 04 §1, the JS initializer, and the shared helpers that implement the twin contract of ADR 04 §3. Built by esbuild from MSBuild (ADR 04 §4); `wwwroot/` is the output and is ignored by git.

## Inputs

- `docs/architecture/*.md`: each mechanism module implements the JS-resident requirements of exactly one architecture document; a component module holds one component's loops (ADR 04 §1, placement rule 2026-10-18).
- `docs/decisions/04-js-interop-boundary.md` §3 (contract, decision points) and §4 (toolchain); ADR 01 (what Server cannot do); ADR 11 §5 (module-graph lint).
- The Base UI source under `reference/` for the algorithms and the vitest titles.
- `node_modules` at the repository root (`package.json`: esbuild, typescript, vitest, `@floating-ui/dom` 1.8.0).

## Job

- `twin.ts`: what every module receives from `attach(elementOrId, optionsJson, dotNetRef, references, captures)` and hands back (`{ update(optionsJson, references, captures), dispose() }`); `captures` (type `TwinCaptures`, ADR 04 Amendments 2026-10-28 and 2026-10-29, design point 9 of M4 track 8) holds the capture ids C# sends whenever an `ElementReference` crosses, the attached element's first, then one per reference: Blazor revives an element inside a shadow root as `null`, and `resolveElement`, `attachTarget` and `resolveReference` find it by `[_bl_<id>]` in the shadow roots the `portal` module registered (`registerShadowRoot`, a page-global map on `globalThis` under `Symbol.for('blazix.shadowRoots')`, counted per registration; the module's one page-global state), and an id no document element carries is looked up there too; `references` (type `TwinReferences`) is the array of elements and script-held objects the options name by index, revived by Blazor and absent when the twin sent none, and `resolveReference(references, options.containerRef)` reads one (the field is each module's: `containerRef`, `anchorRef`, `boundaryRefs`) (ADR 04 Amendments 2026-10-27, element-typed option values, settled by the orchestrator 2026-10-27; M4 track 1); `createTwinChannel` gives a handle its `decide` and `report`, and `synchronous`, whether the twin answers synchronous invocations (WebAssembly), from the probe `decide` uses, so a module can hand state over through a synchronous `[JSInvokable]` method just before a decision (design point 6 of the Tabs track, settled by the orchestrator 2026-10-26); `resolveElement`, `parseOptions`, `applyConsumerStyle` (handover at attach). No module-level registries: a handle's state lives in its closure. The exceptions are `form.ts`'s map from a form's token to its element and controls (design point F6 of M2 track 2, settled by the orchestrator 2026-10-23) and `interactions.ts`'s session map and delay groups (ADR 04 Amendments 2026-10-27). `attachTarget` resolves `attach`'s first argument, `null` being the token form of a part without an element (`AttachTarget`; ADR 04 Amendments 2026-10-27); `decisionPolicies` lists the verdicts' literals. The page-global state ADR 04 Amendments 2026-10-27 sanctions is named in each module's entry with its test reset (`focus-manager.ts`, `scroll-lock.ts`, `interactions.ts`).
- `decide.ts`: `decide(twin, point, event, fallback)`. The render mode is detected from the runtime, per channel, on the first decision: one `Ping` through `invokeMethod`, which Blazor Server's dispatcher rejects synchronously and WebAssembly's answers. WebAssembly then runs the C# chain inside the dispatch; everywhere else the fallback policy is returned without a call.
- `event-info.ts`: the event snapshot. Its property names mirror `Events/EventSnapshot.cs` (Track 2), which is the one place that defines them; `kind` is the DOM interface name.
- `platform.ts`: UTL-ALG-11 as `detectPlatform(navigatorData, webkitBackdrop)`, and `platform`, the page's flags computed once (and frozen) when the chunk loads; the `dom` module owns and re-exports both.
- `dom.ts` (entry `js/dom`): the helpers other modules import: `ownerDocument`, `ownerWindow`, `isElement`, `isHTMLElement`, `isShadowRoot` (exported 2026-10-27 for the focus manager, M4 track 4; a `dom` export a mechanism module needs is that module's own shared edit, one commit with its red test, settled by the orchestrator 2026-10-27), `activeElement`, `contains`, `closest`, `getTarget`; `getCssDimensions`, `getElementTransform`, `getPseudoElementBounds`, `isMouseWithinBounds`, `getElementAtPoint`, `isScrollable(X|Y)`, `findScrollableAncestor`, `findScrollableTouchTarget`, `normalizeScrollOffset`, `getMaxScrollOffset`, `valueToPercent`; `observeResize` and `observeIntersection` (no-ops where the observer does not exist); `markLiveRegion`, `probeImage`, `deriveImageStatus`. Its `attach` runs the primitives `DomTwin` turns on: `checked` (set on attach and on every update, never inside a native click, so a toggle C# accepts is not undone before its commit; `checkedRestores` only makes an unchanged value arrive; re-asserted one task after the owning form's `reset`, switch §16 Q1), `indeterminate`, the live-region marker (after the next paint: one animation frame, then one task; restored 200 ms later if unchanged; never on iOS) and the image status (one report per change; the synchronous pass of a cached image reports only its result; every fallback id in `hideWhenLoaded`, a space-separated list, gets `hidden` the moment the image loads; a kept-mounted `<img>` is re-derived in a `MutationObserver` callback when a render changes its `src`, `srcset`, `sizes`, `crossorigin` or `referrerpolicy`, and that derivation is reported even when it equals the last report, because the element's `load` and `error` events reach C# directly). The Floating UI DOM predicates Base UI imports are re-implemented here so this module stays out of `js/positioning.js`, which bundles the engine. `styleWriter(element)` is the layered-style writer (ADR 04 Amendments 2026-10-27, Decision 2): one writer per element, kept under a symbol so every module entry shares it, with `setConsumer(cssText)` and `layer(name)` returning `{ set(property, value), remove(property), clear() }`. The fixed bands are, under the consumer's string, `positioning` then `transitions`, and over it `positioning-measured` then `auto-resize` (Base UI's order: the positioner styles, `transition: none`, the consumer's style, then the variables written with `setProperty`). A shorthand is held as its longhands, writes are diffed per property, and a module clears its layers when its handle is disposed. `positioning` uses it from M4 track 2; `transitions` and `popup` adopt it in track 5.
- `button.ts` (entry `js/button`): UBT-ALG-01/02 as Base UI writes them, with two port points. A veto from a JavaScript listener that ran before the module (an earlier listener on the element, one on a descendant, or a capture listener on an ancestor) is `event.defaultPrevented`, checked where Base UI checks it; a veto from C# is the verdict of `decide(twin, 'activate', event, 'run')`, asked only where the module is about to act (prevent a key or click). The nested-handler flag is a symbol on the event, set right before each synthetic click, so two handles on one element click once. Also: `dispatchClickWithModifiers`, `isTouchLikePointerType`, `isElementDisabled`, disabled press suppression (click and pointerdown prevented, mousedown left alone), the composite `disabled` property correction, pointer-type classification, the native-mode development check, the press-and-hold repeater whose ticks, release and single-action clicks are reports, the hidden-input bridge (`hiddenInput`, `readOnly`; `findHiddenInput` finds the checkbox or radio input after the element by position; the input's clicks are stopped, a pre-prevented one is ignored, a read-only one reverted, and each toggle asks `decide(twin, 'toggle', click, 'run')`: a refusal on WebAssembly is the input click's `preventDefault()`, and a toggle not decided synchronously is reported as `OnToggle` with the new `checked`), the Enter suppression (`suppressEnter`) of Checkbox and Radio, and the input item (`inputItem`) of Toolbar.Input: no key activates the element and its Space is not prevented, while a disabled, focusable input keeps the non-Tab key prevention and the press suppression (UBT-DOM-12; ADR 04 Amendments 2026-10-26).
- `transitions.ts` (entry `js/transitions`): TRN as a mechanism module. 2026-10-29 (ADR 04 Amendments 2026-10-28, gap 13 of M4 track 5): the element's style goes through `dom`'s `styleWriter`, the handed-over style as its consumer band (in place of `applyConsumerStyle`'s `cssText` overwrite), and `disableTransitionWhileStarting` writes `transition: none` into the `transitions` band while starting (TRN-DOM-05). 2026-10-29 (M4 track 6, found at PR 137's re-merge): each pass writes `hidden` before the transition attributes. A kept-mounted element shown again in the opening pass is then displayed when the attribute writer computes its style with the starting style (0727ec9's flush), so an enter transition runs from it. Before, positioning's layout read after C#'s render covered for the order, until design point 13.4 (1) gave positioning its reference from the session.
  - The page-global frame scheduler: `requestFrame`, `cancelFrame`, `createFrameSlot` and, for tests, `resetFrameScheduler`. Every request made in one task shares one native `requestAnimationFrame`, and cancelling is an O(1) slot.
  - `getFiniteAnimations`.
  - `createAnimationsWatcher(element, waitForStartingStyleRemoved, batch)`, Base UI's `useAnimationsFinished`:
    - the first inspection runs on the next frame, or in the microtask after `data-starting-style` is removed;
    - a canceled animation is re-inspected for its replacement;
    - an abort signal stops the callback, the restart and the observer;
    - `batch` runs the completions ready in one microtask in one flush;
    - a missing element never completes;
    - the callback runs synchronously when `getAnimations` is missing or `globalThis.BASE_UI_ANIMATIONS_DISABLED` is set, read at each wait.
  - `evaluateTransition(state, deferEndingState)`: the evaluation step, a pure function. Its C# twin is `Interop/TransitionStatusRules.Evaluate`; one case table, `test-support/transition-evaluation.cases.json`, is read by the L3 and the L1 tests.
  - `createTransitionMachine(initial, { enableIdleState, deferEndingState }, onCommit)`, Base UI's `useTransitionStatus`: the evaluation step, then the three frame steps, each re-armed only when its dependencies change. `onCommit` is the per-pass hook a component module adds its own pass to.
  - `createTransitionAttributes(element)`: the diff writer of the two attributes.
  - `createHiddenController(element)`: `hidden="until-found"` on a change to hidden, the boolean-to-literal rewrite before paint, and the convergent boolean `hidden` at exit end.
  - `observeOpenInput(element, selector, onChange)`: the open input read from the attributes C# renders, in the `MutationObserver` microtask after the render batch, before paint.
  - `createRevealController(element, { open, request })`: the `beforematch` listener with the `reveal` decision point (fallback `run`, `consumeSkip()` for the opening pass). The revert runs after a 0 ms task and a frame when the request ran inside the dispatch (WebAssembly), and after C#'s answer and a frame otherwise (Server).
  - These factories are what the `collapsible` component module composes with `dom`'s reads. That module is built by the Collapsible track: the orchestrator placed the measurement passes there under the placement rule. This module stays Collapsible-unaware.
  - Its `attach`: the animated part's handle.
    - It starts from the `status` and `mounted` C# rendered (the handover) and is from then on the only writer of `data-starting-style` and `data-ending-style`. Each is written only when its value changes, as a renderer diffs.
    - When it writes `data-starting-style`, or takes over the one C# rendered, it reads the element's computed style once, so the starting style is styled before the clearing frame (ADR 04 Amendments 2026-10-23, C6).
    - With `openSelector` set, the open input is read from the DOM after every batch. A late `update` cannot reopen a part a newer batch closed. Without it, the input is `update`'s `open`.
    - Reports:
      - `OnStatusChange`: status literal and mounted, once per change;
      - `OnTransitionComplete`: `open: false` when an exit finished, standing for the mounted and status change; `open: true` for an enter when `reportOpenComplete`;
      - the invocation `OnRevealRequest`: when no C# chain ran inside the dispatch; it resolves with whether the part is open after the request.
    - Exit end, in the completion pass: it removes `data-ending-style` and sets `hidden` on an element C# is about to remove or hide, which is the convergent write.
    - `hidden="until-found"` while hidden, the persisted `data-starting-style` while hidden, a `MutationObserver` that turns a boolean `hidden` C# renders into the literal before paint, and no `hidden` while open.
    - `unmountRequests` lets C# end an exit it learned of elsewhere; a request that arrives after a reopen is dropped. With `externalExit` no exit watcher is armed, so only such a request ends the exit.
    - The consumer style is applied only when `options.style` is set.
    - A repeated `attach` of the same element returns the live handle (a symbol on the element, not a registry); `dispose` is idempotent.
- `collapsible.ts` (entry `js/collapsible`, a component module): the Collapsible panel's measurement passes (Base UI's `useCollapsiblePanel`), composed from the `transitions` factories (the machine with its per-pass hook, the watchers, the transition attributes, the hidden controller, the open input, the reveal controller, the frame slots) and `dom`'s `ownerWindow`. `Accordion.Panel` attaches it too: `heightVariable` and `widthVariable` name the variables it writes (`--accordion-panel-height/width`), absent for Collapsible's (ADR 04 note dated 2026-10-26); `reportStatus` asks for `OnPanelStatusChange`, the machine's status once per change, for the Item's shared state (D1, settled by the orchestrator 2026-10-26).
  - Per element, a session: animation type detection (`getAnimationType`, reported once per change with the mixed flag); the opening pass (measure and hold the size, the alignment reset until the next frame, the forced idle of a `'none'` or reveal open, the `0s` override of a reveal open kept until the next close); the closing passes (the cached size of a keyframe close, the held size, the zero-size and no-motion exits, the exit watcher one frame after `'ending'`); the open side's completion that clears the held size; the one-shot `animation-name: none`; the persisted starting style and `hidden="until-found"`; the convergent `hidden` at exit end.
  - The element's whole `style` is the module's from `attach`: the consumer's string (`options.style`), then its own declarations (the size variables, the suppression), then the temporary overrides, each restored to what the layers below say.
  - After a closing measurement it computes the element's style, so the closing transition starts from the held size (the ending flip lands in the next frame's callback, before that frame computes styles).
  - `update` re-resolves a disconnected element by `panelId`: a new element starts a fresh session from what C# rendered, and while no element exists an update whose status is `'ending'` ends the exit.
  - Reports: `OnForcedIdleChange`, `OnTransitionComplete` (`open: false`), `OnAnimationTypeChange`, and the reveal (`reveal` decision point, or the `OnRevealRequest` invocation).
- `composite.ts` (entry `js/composite`, a mechanism module): the roving group of CMP, as RadioGroup reaches it, with the M3 extensions of track 1 (ADR 04 Amendments 2026-10-26, chosen by the user; the notes on ADR 04's composite row).
  - The index helpers as CMP §5.1 writes them (`isIndexOutOfListBounds`, `isListIndexDisabled`, `isHiddenByStyles`, `isElementVisible`, `findNonDisabledListIndex`, `getMinListIndex`, `getMaxListIndex`, `getNextListIndex`), `isModifierKeySet`, `getFallbackIndex`, `scrollIntoViewIfNeeded`, `isNativeInput`, `ACTIVE_COMPOSITE_ITEM`, `COMPOSITE_KEYS`, `MODIFIER_KEYS`, and the decision-point names `NAVIGATE_POINT` and `SELECT_POINT`.
  - `createCompositeRegistry()`: the item registry keyed by element (`register(element, { index?, metadata? })`, `unregister`, `flush`, `indexOf`, `subscribe`, `dispose`). One rebuild per `flush` (CMP-ALG-17): document order with explicit slots reserved, disconnected elements and negative indexes left out, publication only on a change. Move detection observes the lowest common ancestor of adjacent automatic items, re-installed after each rebuild, and is a no-op without `MutationObserver`. Explicit indexes and metadata exist on this side only.
  - Its `attach`: the root's handle.
    - It resolves the items' ids from the root's document or shadow root on `attach` and on every `update`, so a replaced element is found again; one `update` that changes the items rebuilds once.
    - The first publication and every later one adjust the highlight (CMP-ALG-18); from `attach` it is the only writer of every item's `tabindex`, `"0"` on the highlighted index and `"-1"` elsewhere, in the task that moves the highlight, never on an item whose registration carries a consumer `tabindex`.
    - `keydown` on the root: CMP-ALG-14 without the grid branch and without `onLoop`. Nothing is prevented or stopped unless the index changes; the decision point `navigate` (fallback `run`) is asked only then, before the module acts; the focus moves one microtask later.
    - `focusin` on the root: the focused item's index becomes the highlight without scrolling; a native text input selects its value; with `selectOnNavigation` and a pending arrow, the item's next-sibling `<input>`, unless disabled or read-only, is clicked with `dispatchClickWithModifiers` after the decision point `select` (fallback `run`), and the flag clears.
    - A capture `keydown` sets the pending flag for any key starting with `Arrow`, with any modifiers. A `focusout` whose related target is outside the root (shadow-aware `contains`, or none) clears it and, when asked, reports `OnFocusLeave`.
    - `mousemove` focuses a hovered, enabled item only with `highlightItemOnHover`. Reports: `OnHighlightChange` (when asked, once per change), `OnFocusLeave`, and `OnKeyHandled` (with `reportHandledKeys`, a key it handled and stopped where no C# chain ran inside the dispatch). It writes no attribute on the root. Handlers read the options of the latest `update`. A repeated `attach` of the same element returns the live handle; `dispose` is idempotent.
    - The items' flags (E3): each registration may carry `disabled` and `focusableWhenDisabled`. With `deriveDisabledIndices` the indices of the items that are disabled and not focusable when disabled replace `disabledIndices`. They are derived in the module's order, in the same pass as each publication and on each `update`, and feed the first publication, the keys and the re-validation, which also runs after each publication.
    - The items report (E2): with `reportItems`, a listener subscribed before the root's adjustment reports `OnItemsChange` `{ ids }`, the ids in index order, on each publication whose id sequence changed (the first in `attach`, one in `update`, an observed move).
    - The registration-only mode (E1): `registrationOnly`, read once at `attach`, keeps the registry and always reports the order. It installs no listener, writes no `tabindex`, keeps no highlight, reads no marker and asks no decision point.
    - The active-item follow (E5): with `followActiveItem`, each item is evaluated as `TabsTab.tsx:83-109`'s effect is, when its marker, its index, the highlight or its `aria-disabled` changed. A keydown on the item (the capture listener's mark) only clears the mark at the next evaluation. Otherwise a marked item whose index differs from the highlight takes it, without scrolling, when focus is outside the root and it is not `aria-disabled="true"` in the applied batch. A `MutationObserver` on the root (`attributeFilter` the marker and `aria-disabled`, `subtree`), installed only with the option, re-checks on a change of either; a publication, a highlight change and an `update` re-check too. The re-validation against the disabled indices does not run (CMP-EDGE-09).
    - Design points 1–6 of track 1 (the report's shape, the item ids, the report's ordering, the follow's trigger and disabled check, the list's context) are settled by the orchestrator 2026-10-26, each option (a).
  - Not built: grid, `onLoop`, the keyed registry (CMP §10 Q1), the keyboard relay, a highlighted index from C# (beyond the follow), metadata from C#, labels and `guess`, list navigation, typeahead.
- `form.ts` (entry `js/form`): the field and form infrastructure's browser half (field half from M2 track 1).
  - Pure helpers: `getDefaultFormSubmitter`, `isEligibleInput` (`:disabled` and the form owner), `readNativeValidity` (the base state, with the field's own message read out), `applyOwnCustomValidity` (the own message and the custom message it displaced, kept on the element under a symbol; `\r\n` and `\r` become `\n`; never written to a barred input), `getControlById` (shadow-aware) and `discoverLabel`.
  - `attach` with `control` options: value tracking (one `input` report per change of the value), `blur`, `keydown` (Enter on an input always, other keys only with `reportKeys`), the Enter commit's 0 ms task when the form owner is the enclosing form, the focus redirect to `focusTarget`, the active-element read at attach and on re-enable, focusing an `autoFocus` control at attach when nothing has focus, and the value ownership from attach (`defaultValue` and the unedited live value; a controlled value re-asserted on `update`). An increased `revision` is answered with a `sync` report, and the custom message is applied from `update`.
  - `attach` with `label` options: the double-click guard on a native label, and on a non-native one `pointerdown` prevented and click-to-focus with `focusVisible`. The nested-control guard walks out of shadow roots. Each step first asks the decision point `label` when the consumer has a pointer handler, and the development mismatch report is sent at attach and when `native` changes.
  - A repeated `attach` of the same element returns the live handle (a symbol on the element).
  - `attach` with `submit` options (a `Form`'s element; the submit half, M2 track 2):
    - every native `submit` is prevented and reported through the invocation `OnSubmitRequest`, with the submitter's id and the value and native validity of every control enrolled on the form;
    - the form's attach registers its element under the token its options carry, in the module's one module-level registry, a `Map<token, { element, controls }>` (settled by the orchestrator 2026-10-23, design point F6: the token is never rendered, and a control and its form attach in either order). A control enrols by the token its `formId` carries and resolves its form at each use; dispose clears both sides;
    - the answer re-issues the submission with `requestSubmit(submitter)` behind a one-shot pass flag, focuses the first invalid control by document order (registration order across disconnected trees) and calls `select()` on an `<input>`, or does nothing;

- `focus-manager.ts` (entry `js/focus-manager`, a mechanism module): FLT's focus manager (ADR 04 §1's `focus-manager` row; the as-built note of 2026-10-27).
  - The tabbable queries, under Base UI's names: `isTabbable`, `focusable`, `tabbable`, `getNextTabbable`, `getPreviousTabbable`, `getTabbableNearElement`, `isOutsideEvent`, `disableFocusInside`, `enableFocusInside` (the `data-tabindex` stash); `portal` and `popup` import them. `isElementVisible` comes from `composite.ts`.

  - The handle, `attach(elementOrId, optionsJson, twinReference, references?)` on the Popup part's element: the open state from the applied batch (`observeOpenInput` with `openSelector`), initial focus (a microtask, then the next frame), the Tab trap, the focus-out close request (once per open; decided in the `focusout`'s microtask and reported at once, or, while the body is the active element, at the next capture `focusin` or a 0 ms task, whichever comes first; ADR 01 Amendments 2026-10-29), restoration, return focus when the manager stops, the managed `tabindex`, the inside guards' routing (`focusin`, as React's `onFocus`; in a portal they fall back to its outside guards) and their VoiceOver `role` written once, and the recorded interaction type reported once per change; the focus-out close re-arms when `answered` moves. - `tabs.ts` (entry `js/tabs`, a component module): the Tabs family's browser half (ADR 04 Amendments 2026-10-26 and 2026-10-27).
  - Pure helpers: `computeActivationDirection` (the two Tabs' `left` or `top`, physical), `getLayoutOffset`, `resolveTranslateLength`, `getActiveTabTranslation`, `measureActiveTab` (the Indicator's arithmetic) and `composeIndicatorStyle` (the six variables, then the consumer's string, whose declarations win). `findOwnTab`, `findOwnTabs`, `findActiveTab`, `findRoot` and `findOwnPanels` read the parts a List owns: those whose nearest List handle is its own (design point 4 of the Tabs track, settled by the orchestrator 2026-10-26).

A click or focus that activates nothing is reported (`OnTabEvent`) only with `reportClicks` or `reportFocus`. - `scroll-lock.ts` (entry `js/scroll-lock`, a mechanism module; M4 track 1, ADR 04 Amendments 2026-10-27, the scroll-lock bullet, chosen by the user 2026-10-27): Base UI's `useScrollLock` as UTL-ALG-01/02 write it. `acquireScrollLock(referenceElement)` returns a once-only release; the lock applies after a 0 ms timer when the count goes from 0 to 1 and releases after a 0 ms timer when it returns to 0; a page already locked by someone else (the viewport scroller's computed `overflow-y` is `hidden` or `clip`) is watched with a `MutationObserver` on `<html>` and `<body>` and taken over when it clears; simple mode (iOS, or no inset scrollbar) writes `overflow-x/y: hidden` on the viewport scroller (`<html>` when `isOverflowElement(html)`, else `<body>`); inset mode exits under WebKit pinch-zoom, takes the gutter path when `CSS.supports('scrollbar-gutter', 'stable')` and the probe keeps the width, and otherwise the full path, which relocks on the next frame after a `resize` (`requestFrame`). Every read and write targets the reference element's document. Its `attach(element, { enabled })` holds one acquisition while enabled; no report, no decision point.

## Toolchain rules

- The csproj target `BlazixBuildJs` runs `node js/build.mjs` before the static-web-assets pipeline enumerates `wwwroot` (`BlazixRegisterJs`, `BeforeTargets="ResolveProjectStaticWebAssets"`), so generated files are packed. `node` is needed at build time only.
- `dotnet build -p:BlazixSkipJsBuild=true` skips the step and fails with a clear message if an output is missing. Verified locally with node off `PATH`:
  1. `dotnet build src/Blazix.Primitives -c Release` with node on `PATH` (produces `wwwroot/`).
  2. `PATH=$(echo "$PATH" | tr ':' '\n' | grep -v node | paste -sd: -) dotnet build src/Blazix.Primitives -c Release -p:BlazixSkipJsBuild=true` → succeeds.
  3. `rm -r src/Blazix.Primitives/wwwroot` then step 2 → fails with the `BlazixRegisterJs` error naming the missing output.
  The manual CI job `.github/workflows/skip-js-build.yml` (ADR 11 §1, [issue 9](https://github.com/JakeMurrayDev/Blazix.Primitives/issues/9)) repeats this on a runner without Node from the `js-outputs` artifact of the latest `main` build: run it before every tagged release.
- Adding a module: a `<BlazixJsEntry Include="js/<module>.ts" Out="js/<module>" />` item, `js/<module>.test.ts` beside it (L3, vitest in jsdom, against `test-support/fake-twin.ts`, which records reports and decisions and behaves like Server or, with `synchronous: true`, like WebAssembly), and a `<Module>Twin` in `Interop/` with its options record in `BlazixJsonContext`.
- L3 titles are Base UI's where a Base UI test observes the module, kept verbatim; other tests carry the port's own titles. Browser-only Base UI tests of a module run at L4 in the page, importing the shipped module (`tests/browser/dom.spec.ts`, the `tabbable` titles of `tests/browser/focus-manager.spec.ts`, and the lazy-flip titles of `tests/browser/positioning.spec.ts`).
- A module that owns no style property never calls `applyConsumerStyle`: `dom` and `button` ignore `style`; `transitions` applies it only when the part hands its style over (`options.style` set).
- A mechanism module never imports a component module (ADR 04 §1); `module-graph.lint.test.ts` (L3, ADR 11 §5) enforces it, and a component module imports only mechanism modules and the shared helpers. `module-graph.lint.ts` holds `moduleKinds`, the one list that names every module's kind: adding a module adds a row there (and amends ADR 04 §1), or the lint fails on the file it does not know. The two `*.lint.*` files and `test-support/` (the L3 fake twin) are not modules of the library.
- `floating-ui.ts` is no module either: the Floating UI wrapper (ADR 04 and ADR 07 Amendments 2026-10-27). It carries the `/*! … */` legal comment naming `@floating-ui/core` 1.8.0, `@floating-ui/dom` 1.8.0 and `@floating-ui/utils` 0.2.12, the MIT licence and the copyright of `THIRD-PARTY-NOTICES.md`, and re-exports ADR 03's eight engine functions, the `@floating-ui/utils` helpers Base UI's positioning layer imports (`clamp`, `evaluate`, `getAlignment`, `getAlignmentAxis`, `getAxisLength`, `getPaddingObject`, `getSide`, `getSideAxis`) and the engine's types. The lint (`floatingUiWrapper`) skips it as a module, accepts its import from `positioning` alone and flags `@floating-ui/*` imported anywhere else, so the engine and its banner stay in `js/positioning.js`. Test files are outside the lint (`positioning.test.ts` imports the engine's own `hide()` to compare against).

## Outputs

- `wwwroot/Blazix.Primitives.lib.module.js` (the initializer) and `wwwroot/js/<module>.js` with `wwwroot/js/chunks/*`, served at `_content/Blazix.Primitives/...` and packed as static web assets.

- Every `decide()` call names its point and its fallback policy from ADR 04 §3; no module moves state through a synchronous invoke (ADR 01 decision 1).
- Every module checks `event.defaultPrevented` where the Base UI source does (ADR 04 Amendments 2026-10-18).
