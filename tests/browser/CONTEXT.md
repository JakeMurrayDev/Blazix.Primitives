# tests/browser

L4: TypeScript specs under `@playwright/test`, one file per family plus the shared suites and the harness's own specs. There is no C# browser test project.

## Inputs

- The fixture host (`../Blazix.Primitives.Fixtures`), started by Playwright's `webServer` with `dotnet run` and polled on `/_fixture/ready`.
- The `Test:` lines tagged `[L4]` in `docs/components/*.md`; decision records 06 §2 (browser harness), 09 §1, 11 (CI) and 14 §3 (`@verifies` tags).
- `playwright.config.ts` at the repository root: projects `server`, `wasm-warmup` (a setup project the `wasm` project depends on) and `wasm`; `retries: 0`, `failOnFlakyTests`; `expect` timeouts as ceilings (WebAssembly larger); the blob reporter in CI.

## Job

Runs every cross-boundary requirement once per render mode. `helpers/`:
- `test.ts`: the `mode` option (`server` | `wasm`), one browser context per worker (pages share its HTTP cache), `page.clock.install()` on every page, running (auto-advancing), so SignalR keep-alive flows on `server` (ADR-06/2).
- `navigation.ts`: `gotoFixture(page, mode, name)` waits for `html[data-blazix-started]` and `[data-fixture][data-interactive="true"]`, never `networkidle`, never a sleep; returns the container locator.
- `circuit.ts`: `delayCircuit(page, oneWayMs)` adds a one-way delay to the Server circuit's WebSocket in each direction through `page.routeWebSocket` (2026-10-27, M4 track 4; moved from `accordion.spec.ts`, which imports it; `checkbox.spec.ts`, `radio-group.spec.ts` and `switch.spec.ts` keep their own copies).
- `session.ts`: `advanceTime(page, container, ms)` moves the page's C# `TimeProvider`; `readDiagnostics(page, mode, container)` reads the captured log entries (endpoint on `server`, page hook on `wasm`).
- `scrollLock.ts` (M4 track 1): `isScrollLocked(page)`, Base UI's `test/scrollLock.ts` (an inline `overflow: hidden` on `<html>` or `<body>`, or `data-base-ui-scroll-locked` on `<html>`), for the popup families' specs.

`suites/` (M4 track 1; ADR 09 and ADR 06 Amendments 2026-10-27, design point 7): Base UI's shared popup suites as Playwright helpers, titles verbatim, which a family's spec calls with a config: `popupConformanceTests`, `detachedTriggersConformanceTests` (both run on the test-only popup host in `popup.spec.ts`), `viewportConformanceTests` and `popupFocusPropsTests` (written for the families to run first). A config names the fixture, Base UI's options, and `open` (a title → the row and track that proves it; the title is skipped with that reason), plus `only` to declare one branch again. The fixture contract (`suites/popupFixture.ts`, C# `PopupSuiteFixtureBase` in the fixture project): the page takes the root's props from its query (`?open=` makes the root controlled; `defaultOpen`, `cancelOpen`, `popupId`, `keepMounted`, `animated`, and each suite's own options documented on its config) and changes a controlled `open` through `[data-set-open="true|false"]`; its container renders `data-open-changes` (space-separated `open:reason` entries), `data-open-change-completes` (space-separated booleans), `data-attached` and `data-sync` (the sync barrier, `settle(fixture)`). Parts carry Base UI's test ids (`trigger`, `popup`, `trigger-1`.., `content`, `root-payload`). States that last an animation are witnessed by `recordAnimationStarts`/`animationStarts` (a capture `animationstart` listener snapshotting the element and the container), never by polling a live style. A route that stalls a library module matches its fingerprinted URL (`/js/<module>(\.[0-9a-z]+)?\.js/`).

Specs (M4 track 1): `popup.spec.ts` (the two suites on `popup-conformance` and `popup-triggers`, PSH-STA-23 per mode on `popup-unmount`), `portal.spec.ts` (the portal on `portal-basic`, issue 8's `@verifies ADR-04/3`, the stalled-module order of the portal and a portaled popup), `scroll-lock.spec.ts`; the CheckboxGroup and RadioGroup portal titles in `checkbox-group.spec.ts` and `radio-group.spec.ts`.

Specs: `smoke.spec.ts` (the probe twin, the harness canary, and the button twin), `button-behavior.spec.ts` (the UBT rows that need only the `button` module; the rest arrive with Button and Toggle in M1), `dom.spec.ts` (the `dom` helpers' browser-only Base UI tests, importing the shipped module in the page), `harness.spec.ts` (the M0 verification items, `@verifies ADR-NN/n` in the title), `wasm-warmup.setup.ts`, then `<family>.spec.ts` from M1 (`field.spec.ts`, `fieldset.spec.ts`, `input.spec.ts` from M2 track 1, `form.spec.ts` from M2 track 2 (a page-added submit listener records the submitter and `defaultPrevented` of each submit event and stops a re-issued one's navigation): the Field-only [L4] titles, waiting on `data-attached` and the sync barrier). `collapsible.spec.ts` catches a state that lasts less than a frame with a `MutationObserver` or a per-frame poll in the page rather than `expect`'s interval, and measures ADR 01's verification item 2 with a delay added to the circuit's WebSocket through `page.routeWebSocket` (Chromium's network emulation does not delay it). `composite.spec.ts` (M2 track 3) is a mechanism's spec on the test-only `composite-*` fixtures: Base UI's composite root is internal, so the CMP rows no public part hosts yet run there, and RadioGroup's spec proves them again through a public part. M3 track 1 adds the extensions' titles. "keeps outer metadata and focus navigation when items share a DOM node" runs on `composite-nested`. The flag change, the follow and the registration-only list run on `composite-flags`, `composite-follow` and `composite-registration`. Each per-mode timing is witnessed by the records of a `MutationObserver` the page adds (the delivery that carries the change; `attributeOldValue` for a value a later batch of the same task overwrites). A change to it runs full L4: `js/` is a shared path and `Composite/` is not a family folder (`.github/CONTEXT.md` §Scoped L4). `focus-manager.spec.ts` (M4 track 4) is the same kind of mechanism spec on the test-only `focus-manager-*` fixtures: FLT-FOC-12's browser-only titles, FLT-DOM-15's guard port titles, the focus-out close's timing per mode, "non-modal + FloatingPortal" on `focus-manager-portal` (FLT-DOM-14's cited title; the publication, the outside guards' routing and the stash on composite items, 2026-10-28) and the open input under latency (a `MutationObserver` the page adds records each `data-open`, `aria-hidden` and `data-base-ui-inert` write with its animation-frame number), plus `tabbable.test.ts`'s six browser-only titles, importing the shipped module in the page as `dom.spec.ts` does.

## Outputs

- Playwright reports, traces and blob reports under `playwright-report/`, `test-results/` and `blob-report/` (ignored by git).
- Run by the `browser-server` and `browser-wasm` CI jobs: on a pull request a change confined to one family's folder or spec files runs that family's `<family>.spec.ts` files in both modes, a shared path or the label `full-l4` runs everything, and documents-only changes run none (`.github/scripts/classify-paths.mjs`, rule in `.github/CONTEXT.md`); on `main` everything over four shards; nightly everything with `--repeat-each 3` over four shards. Two shards on a pull request; the blob reports are merged into one HTML report artifact.
- The `red-check` job lists the tests here on the merge base and on the head (`playwright test --list --reporter=json`), and runs the spec files with added tests against the base's `src/` with these specs and the fixture host; a test that passes there fails the pull request. Tests added in a spec must fail against the base mode by mode.

## Human check

- Each title keeps Base UI's wording and its `@verifies` tag where a verification item applies.
- Gesture tests use real Playwright mouse and touch input, not `dispatchEvent`.
- `retries` stays 0; a flaky test is quarantined with `test.fixme`, `@quarantine` and an issue, for at most 14 days. The nightly summary counts the quarantined specs and reports any flaky result (there can be none while `retries` is 0).
- A test that needs frozen time pauses the clock itself; nothing waits on a timeout.
